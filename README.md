# Community Builders of Pecan Grove · student play-test

A test copy of the kids' civic game from the Know Your Data Center hub, for students to play and review before the public launch.
English: `index.html` · Spanish: `espanol.html`. Built by `tools/make_playtest.py` in the hub project; do not edit here.

The game saves progress and feedback drafts in the player's browser (localStorage). When the playtest receiver is configured, a note leaves the device only after a grown-up reviews its scrubbed preview, ticks the grown-up check and chooses Send. Score sharing starts off and needs a grown-up's confirmation; with its second box on, each finished stop's score is sent right away. Shared computers have **Next player on this computer** for separate game and feedback sessions. Next player never leaves a player's notes behind for the next child: notes the playtest team has not received are first reviewed and sent (**Review and send now**, with the grown-up check; only when a receiver is configured), deleted (**Delete them**, after a second question whose default is Keep playing) or, only in a build with a facilitator's close-out code, kept on the device for the facilitator (**Keep them for the facilitator**). If saving stops working, Next player offers to erase this device's Pecan Grove data and start over. **Privacy and notes on this device** (under For grown-ups) holds the privacy notice, a count of the notes saved on the device and an erase-all control; it never shows one player's notes to the next player. Reading, sending and downloading every player's notes, and bringing back a player chosen by mistake, happen only in **Facilitator close-out** (see below), which exists only in a build with a close-out code. No names or contact details are requested.

Excel files hold every note with the same scrub as a sent note, under a first row that asks to check the file before sharing: the per-player **Download Excel backup** (only in copies with no receiver, such as the library copy) and the facilitator's Excel for every player. A file stays in the computer's Downloads folder, so when one was downloaded during a player's turn, Next player and closing the close-out say to delete it.

The game also keeps a short list of recent game steps on the device (screen, stop number, animal slot and language; no names, typed text or scores) so a grown-up can see where play got stuck. Only the eight most recent players on a device keep a step log; older logs are removed. It is never sent. In the game, For grown-ups > Progress file saves the saved games, badges and these steps as a local JSON file, and opens such a file on this or another device. The file is checked before anything changes and is never sent.

Known limit: GitHub Pages serves this game from the shared `a2-learning-studio.github.io` origin, so any other page published under that account can read this game's browser storage, including unsent drafts and notes kept for the facilitator. The game re-checks each queued note's scrub before sending it, but only a dedicated origin (for example a custom domain) removes that read risk. The facilitator's close-out code keeps children out; it is not strong security. The page carries a salted SHA-256 hash of the code, so a determined person with the page source could try codes offline, and wrong tries are limited only per browser tab (five, then a one-minute wait). Use a code of 6 or more characters (longer is better), keep it off shared screens and paper a child can see, and change the secret if a child may have seen it. The scrub and the words-to-check flags are heuristics, so a grown-up still reads every note. Downloaded files stay in Downloads until someone deletes them. On a shared computer, erase the device's Pecan Grove data when the session ends.

## For grown-ups and educators

- **Closing out a play-test (facilitator).** A build made with a close-out code (see For developers) has **Facilitator close-out** under For grown-ups, on the start page and in the game. Choose it, type the code into the dialog (never into the address bar, so nothing reaches the browser's history) and choose **Open close-out**. The close-out lists every player's notes on the device as Send would send them (scrubbed, with words to check), sends the ones the playtest team has not received after one grown-up check, downloads a scrubbed Excel file for every player and brings back a player if someone chose Next player by mistake. Send sends only the notes on the list as shown: a note written or changed in another tab redraws the list and clears the check. Closing it after a download reminds you to delete the file from Downloads; leaving the page closes it, and Back or Forward never shows it again. A build without a code has no close-out at all: Next player then sends or deletes each player's notes, and a Next player chosen by mistake cannot be undone. The educator sheets, the game and the published site never say how to open the close-out; only this README and `docs/` do, and neither is part of the built site.
- **Educator sheets.** Every build ships `educator.html` (English) and `educador.html` (Spanish) beside the game, and **For grown-ups** in the game links to them. Page 1 prints on one US Letter page: learning goals, grouping, words to know and "Try it for real" tasks. Page 2 lists the sources of the game's real-world facts. `tools/make_educator.py` builds both sheets from the game's locale files and `docs/fact-sources.json`.
- **Real-world facts.** Pecan Grove is made up, but Stop 10's 16 fix cards name real places and some grown-up notes describe Georgia law. `docs/fact-sources.json` records their sources, the date they were checked and the corrections contact; `npm run check:fact-sources` fails when a claim lacks a source or its wording changed after the check (see [docs/quality-checks.md](docs/quality-checks.md)).
- **Family copy for IT.** [docs/family-build.md](docs/family-build.md) explains the copy with no feedback connection: how to get it, host it and check it.

## For developers

- Build with Node 24 and the Python packages in `tools/requirements-build.txt`: `npm run build` writes the play-test to `dist/`, and `npm run build -- --flavor=family` writes the family copy to `dist-family/`. A local build has no feedback receiver unless `PG_FEEDBACK_ENDPOINT` or `backend/feedback/deployment.json` provides one ([backend/feedback/README.md](backend/feedback/README.md)).
- **Facilitator close-out code.** `PG_CLOSEOUT_CODE` (an environment variable, read by `tools/build.mjs` and `tools/make_playtest.py` like `PG_FEEDBACK_ENDPOINT`) turns Facilitator close-out and **Keep them for the facilitator** on, for the playtest flavor only; the family and library copies never get it. The code reaches the Python builder only through the environment, never the command line, and the built page carries only a random per-build salt and the SHA-256 hash of salt and code. Without a code, the close-out and the keep option do not exist. In GitHub, add a repository secret named `PG_CLOSEOUT_CODE` (6 or more characters); the workflow passes it to the deployed playtest build when it is set. Tell facilitators the code in person, not on the educator sheet. Changing the secret and deploying changes the code.
- CI (`.github/workflows/modernization.yml`) runs the unit tests with coverage (`npm run test:coverage`; `npm run test:unit` runs them without coverage), `python -B -m unittest discover -s tools/tests -p 'test_*.py'`, `npm run lint`, `npm run lint:css`, `npm run format:check`, `npm run check:no-emoji`, `npm run check:fact-sources`, the play-test, family and library builds and `npm run test:privacy-copy`, then the Playwright suite (`npm run test:e2e`) against `dist-e2e`, a copy built with a placeholder receiver and the known test close-out code `e2e-closeout-test-code` that is never deployed, and Lighthouse. `npm run test:coverage`, `npm run images` and `node tools/readability.mjs` rewrite tracked reports and images.
- `tools/build.py`, `tools/make_handout.py` and `tools/integrate_feedback.py` belong to the Know Your Data Center hub workflow; nothing in this repository's build, tests or CI runs them, and `tools/build.py` refuses to run here because it empties `docs/`. `tools/integrate_reviewed_changes.py` is an owner tool for the hub copy, covered by its own test.
- The runtime loads stops from `assets/games/community-builders/stops/manifest.json`; `stops/manifest.js` is the module list that `tools/validate_game.mjs` checks.
