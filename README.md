# Community Builders of Pecan Grove · student play-test

A test copy of the kids' civic game from the Know Your Data Center hub, for students to play and review before the public launch.
English: `index.html` · Spanish: `espanol.html`. Built by `tools/make_playtest.py` in the hub project; do not edit here.

The game saves progress and feedback drafts in the player's browser (localStorage). When the playtest receiver is configured, a note leaves the device only after a grown-up reviews its scrubbed preview, ticks the grown-up check and chooses Send. Score sharing starts off and needs a grown-up's confirmation; with its second box on, each finished stop's score is sent right away. The feedback panel also downloads an Excel-compatible backup. Shared computers have **Next player on this computer** for separate game and feedback sessions. **Privacy and notes on this device** (under For grown-ups) holds the privacy notice, a count of the notes saved on the device and an erase-all control; it never shows one player's notes to the next player. Reviewing, sending and downloading every player's notes, and bringing back a player chosen by mistake, happen only in the grown-up close-out view (see below). No names or contact details are requested.

The game also keeps a short list of recent game steps on the device (screen, stop number, animal slot and language; no names, typed text or scores) so a grown-up can see where play got stuck. Only the eight most recent players on a device keep a step log; older logs are removed. It is never sent. In the game, For grown-ups > Progress file saves the saved games, badges and these steps as a local JSON file, and opens such a file on this or another device. The file is checked before anything changes and is never sent.

Known limit: GitHub Pages serves this game from the shared `a2-learning-studio.github.io` origin, so any other page published under that account can read this game's browser storage, including unsent drafts. The game re-checks each queued note's scrub before sending it, but only a dedicated origin (for example a custom domain) removes that read risk. The close-out view below is a deterrent, not security: it keeps earlier players' notes out of a child's way in the normal game, but anyone who knows its address can open it and confirm the grown-up check. On a shared computer, erase the device's Pecan Grove data when the session ends.

## For grown-ups and educators

- **Closing out a play-test.** At the end of a session, open the game as `index.html?closeout=1` (Spanish: `espanol.html?closeout=1`) and choose **I am the grown-up running the play-test**. The close-out view lists every player's notes on the device (scrubbed, with words to check), sends the ones the playtest team has not received after one grown-up check, downloads an Excel file for every player (it has each note as written, so keep it private) and brings back a player if someone chose Next player by mistake. Send sends only the notes on the list as shown: a note written or changed in another tab redraws the list and clears the check. The address drops `?closeout=1` once the question is answered, and the educator sheets describe the same switch.
- **Educator sheets.** Every build ships `educator.html` (English) and `educador.html` (Spanish) beside the game, and **For grown-ups** in the game links to them. Page 1 prints on one US Letter page: learning goals, grouping, words to know and "Try it for real" tasks. Page 2 lists the sources of the game's real-world facts. `tools/make_educator.py` builds both sheets from the game's locale files and `docs/fact-sources.json`.
- **Real-world facts.** Pecan Grove is made up, but Stop 10's 16 fix cards name real places and some grown-up notes describe Georgia law. `docs/fact-sources.json` records their sources, the date they were checked and the corrections contact; `npm run check:fact-sources` fails when a claim lacks a source or its wording changed after the check (see [docs/quality-checks.md](docs/quality-checks.md)).
- **Family copy for IT.** [docs/family-build.md](docs/family-build.md) explains the copy with no feedback connection: how to get it, host it and check it.

## For developers

- Build with Node 24 and the Python packages in `tools/requirements-build.txt`: `npm run build` writes the play-test to `dist/`, and `npm run build -- --flavor=family` writes the family copy to `dist-family/`. A local build has no feedback receiver unless `PG_FEEDBACK_ENDPOINT` or `backend/feedback/deployment.json` provides one ([backend/feedback/README.md](backend/feedback/README.md)).
- CI (`.github/workflows/modernization.yml`) runs the unit tests with coverage (`npm run test:coverage`; `npm run test:unit` runs them without coverage), `python -B -m unittest discover -s tools/tests -p 'test_*.py'`, `npm run lint`, `npm run lint:css`, `npm run format:check`, `npm run check:no-emoji`, `npm run check:fact-sources`, the play-test, family and library builds and `npm run test:privacy-copy`, then the Playwright suite (`npm run test:e2e`) against `dist-e2e`, a copy built with a placeholder receiver that is never deployed, and Lighthouse. `npm run test:coverage`, `npm run images` and `node tools/readability.mjs` rewrite tracked reports and images.
- `tools/build.py`, `tools/make_handout.py` and `tools/integrate_feedback.py` belong to the Know Your Data Center hub workflow; nothing in this repository's build, tests or CI runs them, and `tools/build.py` refuses to run here because it empties `docs/`. `tools/integrate_reviewed_changes.py` is an owner tool for the hub copy, covered by its own test.
- The runtime loads stops from `assets/games/community-builders/stops/manifest.json`; `stops/manifest.js` is the module list that `tools/validate_game.mjs` checks.
